# Retro Set: guide for AI assistants and developers

This is the main guide for anyone, person or AI, who changes this project. Claude Code reads it through `CLAUDE.md`; other AI coding tools (OpenAI Codex, Cursor, GitHub Copilot and others) read `AGENTS.md` directly. ## Start here

**What it is.** Retro Set will be a 3D pixel-art chess game, a sister to the owner's pool game Retro Rack (https://github.com/flopp-r/retro-rack, live at https://flopp-r.github.io/retro-rack/). Like Retro Rack it is one self-contained web page, hosted on GitHub Pages from this repository, and installable as an app. Live (once GitHub Pages is switched on): https://flopp-r.github.io/retro-set/

**Where it's up to.** The working setup is in place, copied from Retro Rack: this guide and the other notes, the one-file build, the context packs, the tests, and the installable app. The page itself is a placeholder: the title screen in front of an empty board, drawn with Retro Rack's pixel-art pipeline. The game (rules, pieces, menus, opponents) hasn't been designed yet; the decisions waiting for the owner are listed in `HANDOVER.md` (section 4). Agree each one with the owner before building it.

**Read in this order**
1. This file: how it works, the rules, and how to test and ship a change.
2. `HANDOVER.md`: why things are the way they are, reference numbers, the decisions still to make, and a dated list of every change shipped.
3. `README.md`: how the owner set it up, and what players see.
4. The code: `src/core.js` (the chess rules and the computer player, to come), then `src/game.js` (everything in the browser). Both are split into sections marked `// ------ name`; the map in `CONTEXT.md` lists them with line numbers.

**Rules that must never be broken**
1. **`index.html` is built output.** Edit `src/`, then run `node tools/build.js`, and commit both.
2. **A clean console:** no errors, warnings or deprecated APIs.
3. **`main` is live.** Pushing to `main` deploys the site. Work on a branch and test first.
4. **`src/core.js` has no DOM.** The rules and the computer player must also run in Node, for the tests and tools.
5. **The repository is public.** Never commit personal details, passwords, tokens or keys.
6. **Once there is online play:** both browsers must agree on every position, and both players need the same version. Ask the owner before changing online messages or behaviour, and keep old fields working where possible.

## Project conventions

- Explain changes in plain language, say what will change on screen, and keep jargon out of summaries.
- UK English and metric units everywhere: in the UI, comments and messages.
- Ask before large redesigns, as well as before anything that changes online play (rule 6 above).
- Every menu screen must fit a phone held sideways (762×341) without scrolling. A long list may scroll inside its panel; the screen itself still fits.
- Code style: match the file you're in. Compact, mostly one statement per idea, comments only where the reason isn't obvious. No build step beyond `tools/build.js`, and no frameworks or npm packages in the game.
- Browser storage keys start with `retroSet.` (Retro Rack's start with `retroRack.`, so the two games never read each other's saves on the same site). Wrap every access in try/catch: storage can be missing or blocked.

## Architecture

### Core (`src/core.js`)
- One object, `CORE`, made inside a function so nothing leaks into the page; at the bottom, `module.exports = CORE` when running in Node. The build puts it first in the page, so `game.js` uses it as `C`.
- Today it holds `START`, the standard starting position in FEN (Forsyth–Edwards Notation: the pieces rank by rank from Black's side, then who moves, castling rights, the en passant square, the halfmove clock and the move number).
- To come, once agreed with the owner: the board, legal moves (castling, en passant, promotion), check, mate and the draws, and the computer player. Two habits carried over from Retro Rack, because they made its tests and online play dependable:
  - No `Math.random` in `core.js`: anything random (the computer's choice between equal moves, say) takes a seeded generator, so a test or a replay repeats exactly.
  - The computer player as a generator (`function*`), so its search can be spread across frames and the page never freezes (see `planBot` in Retro Rack's `core.js`).

### Browser (`src/game.js`)
- **Rendering** (the renderer + post section, the same as Retro Rack's): the scene is drawn at low resolution into a render target; a post-processing shader then adds outlines where the depth jumps, a vignette and, below full colour, Bayer dithering and colour quantisation; the canvas is scaled up with hard pixel edges. Lights use three.js physical units; colour management is off, so colours appear exactly as written. `resize()` sets the drawing size from `S.pixel` (game pixels per screen pixel; 0 is Max, one per real screen pixel, as in Retro Rack).
- **Settings:** `S` in localStorage (`retroSet.settings`), with `DEFAULTS` at the top of the file: `pixel` 1 and `levels` 256 (the sharpest picture), `dither` and `outline` on. There is no Settings panel yet.
- **The scene** (placeholder): a dark floor, a round wooden table and an empty board (8 × 5.7 cm squares with a 3 cm border, a light square at each player's right), lit by a hemisphere light, a directional light and a lamp. Behind the menu the camera circles slowly (`cam`); with reduced motion it holds still. `frameBoard()` shifts the picture (`camera.setViewOffset`) so the board sits in the space the menu panel leaves, to its right or, on an upright phone, below it, and moves the camera back on screens narrower than they are tall.
- **States:** `state` is `menu` for now; the game's states come with the game.
- **Installable app:** `game.js` adds the manifest link and registers `sw.js` only on http(s), so a copy opened from disk stays quiet. The version line (`#ver`) shows `BUILD`, which `tools/build.js` stamps with a fingerprint of the game code.
- **For the tests:** `window.__rs` gives the state, the frame count, the triangles drawn each frame, the settings and the starting position, so tests can check the page without reaching into its internals. Add to it as the game grows (Retro Rack's `window.__rr` is the model).

### Page (`src/shell.html`)
- The markup and all the CSS. The palette (`:root`), the fonts and the panel and button styles are Retro Rack's. The menu is a panel on the left (`#menu`, `#menuPanel`) holding a stack of screens (`#mStage`, `.mScreen`); there is one screen (`sc-home`) for now. The media query for short screens (500 px or less) is the phone-on-its-side layout.

### Online play
Not built. If the owner chooses it, follow Retro Rack's design: the browser in each seat runs the full game and a small relay only forwards messages; the receiver checks every move is legal with `core.js` before playing it, and both sides compare positions after each move; the version check before a game starts; reconnecting by a per-tab client id. Chess sends moves, not physics, so agreeing on positions is far easier than in pool, but the version check still matters, because a rules change would make the two browsers disagree.

## Testing

1. **Core:** `node tests/core.test.js` must report 0 failed. Today it checks that `core.js` runs in Node, the starting position, and that `CONTEXT.md` and `CONTEXT-SHORT.md` match the code and notes (if not, run the build). The rules tests go here as the rules are built: every special move, check, mate, stalemate and each draw, and known positions with a known number of legal moves (perft counts) to catch move-generation bugs.
2. **Browser tests:** `node tests/browser/run-all.js` builds the game, serves a copy of it locally like GitHub Pages (under `/retro-set/`, on port 8180, so Retro Rack's tests can run at the same time), then runs every `*.test.js` in `tests/browser/` in headless Chromium and prints a summary. Each check prints `PASS` or `FAIL`, and each file also fails if anything reaches the browser console.
   - Needs Playwright with Chromium (preinstalled in Claude Code's cloud sessions; elsewhere `npm install --no-save playwright` then `npx playwright install chromium`). Nothing is written into the repository; screenshots go to a temporary folder, printed at the end.
   - Software rendering is slow, so `lib.js` starts test pages at pixel size 3× and 8 shades rather than the game's sharper defaults, unless a test sets its own settings or opens the page with `?realdefaults` (as the check of the defaults does). Keep test windows small (about 480×360) unless the size is what's being tested.
   - The files: `file` (the page opened from disk: the version, no install bits, the board drawn, the real defaults), `fit` (the menu fits at phone, tablet and computer sizes, including a phone on its side), `app` (installable app, offline start, updates arriving; over http).
   - New features get a new test file, or new checks in the file that fits. A test that reloads a page or uses two pages needs storage to carry over, so it runs over http (`SITE.new`), not from disk.
3. **By eye:** for gameplay or UI changes, open `index.html` in a browser and try the change, watching the console.

## 4. Key decisions and why

**Delivery (carried over from Retro Rack)**
- **One self-contained `index.html`,** with fonts and three.js inlined, so the game works offline as a single downloaded file and GitHub Pages can serve it with no build step on the server.
- **three.js is pinned at r159** (ES-module build, wrapped by `tools/build.js`), the same file as Retro Rack's, so code ported between the games behaves the same. Upgrading is possible but not needed; if you do, re-check lighting, the `DepthTexture` outline pass and the console.
- **The same pixel-art look:** Retro Rack's low-resolution render target and post-processing shader (outlines, vignette, dithering), its palette and its fonts, so the two games look like a family.
- **The version is a fingerprint of the code,** shown at the bottom of the menu, so the owner can see an update has arrived (and, if online play comes, players can compare versions).
- **The context packs** (`CONTEXT.md`, `CONTEXT-SHORT.md`) are remade by every build and checked by the tests, so any AI can be given the whole project in one file and it's never out of date.
- **Separate from Retro Rack:** its own repository, site, storage keys (`retroSet.` rather than `retroRack.`) and, if online play comes, its own relay, so a change to one game can't break the other. Code is shared by copying, not by a shared library, because each game is one self-contained page.

**Decisions still to make (each to be agreed with the owner before it's built)**
1. **The look of the game.** The setup assumes 3D pixel art like Retro Rack (three.js and the pixel-art pipeline are in place). A 2D pixel-art board is the alternative: simpler and lighter on phones, but less like Retro Rack. If 2D is chosen, three.js and the pipeline come out.
2. **Who you play:** the computer (and how many skill levels), two people on one device, online against a friend (needs a relay, as in Retro Rack), or a mix. This decides the order of the work.
3. **How much of the rules:** the full rules (castling, en passant, promotion to any piece, checkmate and stalemate, and the draws: threefold repetition, the fifty-move rule, insufficient material, agreement), and whether to have clocks.
4. **The set itself:** the style of the pieces (classic Staunton shapes in pixel art, or something more playful), the board, and the room.
5. **Later extras, if wanted:** puzzles (as Retro Rack has trick shots), a career against named computer players, looks to earn (boards, piece sets, rooms), a replay of the game move by move.

// stand behind the title screen while the game itself is agreed with the owner (see AGENTS.md and HANDOVER.md).

'use strict';

const $ = s => document.querySelector(s);
const clamp = (v, a, b) => v < a ? a : v > b ? b : v;

// ------------------------------------------------------------------ settings
// pixel: game pixels are this many screen pixels across (0 is Max: one per real screen pixel); levels: shades per
// colour channel (256 is full colour; fewer turns on the dithering)
const DEFAULTS = { pixel: 1, levels: 256, dither: true, outline: true };
const S = { ...DEFAULTS };
try { Object.assign(S, JSON.parse(localStorage.getItem('retroSet.settings') || '{}')); } catch (e) {}

// ------------------------------------------------------------------ renderer + post
// The scene is drawn small into a render target, then a shader adds outlines where the depth jumps, a vignette and,
// below full colour, Bayer dithering; the canvas is scaled up with hard pixel edges. The same pipeline as Retro Rack.
const canvas = $('#view');
const renderer = new THREE.WebGLRenderer({ canvas, antialias: false, powerPreference: 'high-performance' });
THREE.ColorManagement.enabled = false;
renderer.outputColorSpace = THREE.LinearSRGBColorSpace;
renderer.setPixelRatio(1);
renderer.info.autoReset = false;   // counted per frame (see the main loop), so the tests see the scene, not just the last pass
const scene = new THREE.Scene();
const ROOM = new THREE.Color('#1a1433');
scene.background = ROOM;
scene.fog = new THREE.Fog(ROOM, 4, 11);
const camera = new THREE.PerspectiveCamera(40, 1, 0.03, 12);   // seeing no further than the fog: the floor fades out with no edge for the outlines to find

const postMat = new THREE.ShaderMaterial({
  uniforms: {
    tColor: { value: null }, tDepth: { value: null }, uRes: { value: new THREE.Vector2(1, 1) },
    uLevels: { value: 8 }, uDither: { value: 1 }, uOutline: { value: 1 }, uNear: { value: camera.near }, uFar: { value: camera.far },
  },
  vertexShader: 'varying vec2 vUv; void main(){ vUv = uv; gl_Position = vec4(position.xy, 0.0, 1.0); }',
  fragmentShader: `
    uniform sampler2D tColor; uniform sampler2D tDepth; uniform vec2 uRes;
    uniform float uLevels, uDither, uOutline, uNear, uFar;
    varying vec2 vUv;
    float linZ(float d){ return uNear*uFar/(uFar - d*(uFar-uNear)); }
    float b2(vec2 v){ return mod(2.0*v.x + 3.0*v.y, 4.0); }
    float bayer4(vec2 p){ vec2 q = mod(floor(p), 4.0); return (4.0*b2(mod(q,2.0)) + b2(floor(q/2.0)) + 0.5)/16.0; }
    void main(){
      vec2 px = 1.0/uRes;
      vec3 col = texture2D(tColor, vUv).rgb;
      if (uOutline > 0.5) {
        float dc = texture2D(tDepth, vUv).x;
        float dl = texture2D(tDepth, vUv - vec2(px.x,0.0)).x, dr = texture2D(tDepth, vUv + vec2(px.x,0.0)).x;
        float dd = texture2D(tDepth, vUv - vec2(0.0,px.y)).x, du = texture2D(tDepth, vUv + vec2(0.0,px.y)).x;
        float zc = linZ(dc);
        float lap = abs(dl + dr - 2.0*dc) + abs(du + dd - 2.0*dc);
        float dz = lap * zc*zc*(uFar-uNear)/(uNear*uFar);
        float zmax = max(max(linZ(dl),linZ(dr)), max(linZ(du),linZ(dd)));
        float edge = step(0.02*zc + 0.012, dz) * step(0.03*zc + 0.015, zmax - zc);
        if (dc >= 0.99999) edge = 0.0;
        col = mix(col, col*0.22 + vec3(0.035,0.025,0.07), edge*0.9);
      }
      vec2 c = vUv - 0.5; col *= 1.0 - 0.55*dot(c,c);
      if (uLevels < 200.0) {
        float t = (bayer4(gl_FragCoord.xy) - 0.5) * uDither;
        col = floor(col*(uLevels-1.0) + 0.5 + t) / (uLevels-1.0);
      }
      gl_FragColor = vec4(clamp(col,0.0,1.0), 1.0);
    }`,
  depthTest: false, depthWrite: false,
});

## sw.js

Service worker for the installable app (network first). (44 lines)

```js
// Retro Set service worker: lets the installed game start without internet.
// Network first, always: when online, every file comes fresh from the site (so updates arrive straight away and,
// once there is online play, both players get the same version); the saved copy is used only when the network fails.
const CACHE = 'retro-set';
const FILES = ['./', 'manifest.webmanifest', 'icons/icon-192.png', 'icons/icon-512.png'];

self.addEventListener('install', e => {
  e.waitUntil(caches.open(CACHE)
    .then(c => c.addAll(FILES.map(f => new Request(f, { cache: 'no-cache' }))))
    .then(() => self.skipWaiting()));
});

self.addEventListener('activate', e => {
  e.waitUntil(caches.keys()
    .then(keys => Promise.all(keys.filter(k => k !== CACHE).map(k => caches.delete(k))))
    .then(() => self.clients.claim()));
});

self.addEventListener('fetch', e => {
  const req = e.request, url = new URL(req.url);
  if (req.method !== 'GET' || url.origin !== location.origin) return;
  // the game is one page, so every visit to it shares one saved copy, whatever comes after the ? or #
  const home = new URL('./', self.registration.scope);
  const page = req.mode === 'navigate' && (url.pathname === home.pathname || url.pathname === home.pathname + 'index.html');
  if (req.mode === 'navigate' && !page) return;   // other pages on the site (README and so on) aren't the game
  const key = page ? home.href : req;
  e.respondWith((async () => {
    try {
      // 'no-cache' checks with the site each time (cheap when nothing changed) instead of trusting the browser cache
      let res = await fetch(page ? req.url : req, { cache: 'no-cache', credentials: 'same-origin' });
      if (page && res.redirected) res = await fetch(req);
      if (res.ok && res.type === 'basic') {
        const copy = res.clone();
        e.waitUntil(caches.open(CACHE).then(c => c.put(key, copy)));
      }
      return res;
    } catch (err) {
      const saved = await caches.match(key, { ignoreSearch: true });
      if (saved) return saved;
      throw err;
    }
  })());
});
```

// Builds index.html from src/ and vendor/. Run with:  node tools/build.js   (no installs needed)
// Output is one self-contained file: fonts and the three.js engine are inlined so it also works offline.
// It then remakes CONTEXT.md and CONTEXT-SHORT.md, the one-file summaries of the project for AI assistants.
const fs = require('fs'), path = require('path'), crypto = require('crypto');
const root = path.join(__dirname, '..');
const read = p => fs.readFileSync(path.join(root, p), 'utf8');
const b64 = p => fs.readFileSync(path.join(root, p)).toString('base64');

// the game code, in this order; a new file in src/ goes in this list (and in SOURCE in make-context.js)
const CODE = ['src/core.js', 'src/game.js'];

let html = read('src/shell.html');
html = html.replace('__PS2P__', () => b64('vendor/press-start-2p-latin-400-normal.woff2'));
html = html.replace('__VT323__', () => b64('vendor/vt323-latin-400-normal.woff2'));
html = html.replace('__FAVICON__', () => b64('icons/favicon-32.png'));   // inlined, so a downloaded copy has it too

// three.js ES module build: turn its single trailing `export {...}` into a returned namespace object,
// so it can live inside one inline <script type="module"> with the game code.
let three = read('vendor/three.module.min.js').trimEnd();
const m = three.match(/export\s*\{([^}]*)\}\s*;?\s*$/);
if (!m || (three.match(/export/g) || []).length !== 1) throw new Error('Unexpected three.js module format');
const pairs = m[1].split(',').map(s => s.trim()).filter(Boolean).map(part => {
  const [loc, pub] = part.split(/\s+as\s+/);
  return `${(pub || loc).trim()}:${loc.trim()}`;
});
three = three.slice(0, m.index) + 'return Object.freeze({' + pairs.join(',') + '});';

let bundle = 'const THREE = (() => {\n' + three + '\n})();\n' + CODE.map(read).join('\n');
if (bundle.includes('</script')) throw new Error('Bundle contains </script, which would break the page');
// The version is a fingerprint of the game code: any code change gives a new one, an unchanged rebuild the same.
// It shows at the bottom of the menu, so the owner can check an update has arrived (and, once there is online
// play, the two players can compare versions before a game starts, because both must run identical code).
const version = crypto.createHash('sha256').update(bundle).digest('hex').slice(0, 8);
if (bundle.split("'__BUILD__'").length !== 2) throw new Error("Expected exactly one '__BUILD__' in the game code");

// the pawn's half-width on a row (grid pixels), or 0 where the row isn't part of it; py is the row's middle
function half(px, py) {
  const head = 4.3, hy = 9.2;
  if (Math.abs(py - hy) <= head) { const w = Math.sqrt(head * head - (py - hy) ** 2); if (Math.abs(px - CX) <= w) return w; }
  if (py >= 13.5 && py < 15.3) return 4.6;                                  // collar
  if (py >= 15.3 && py < 21.5) return 2.4 + 2.8 * ((py - 15.3) / 6.2) ** 1.6;   // body, flaring out
  if (py >= 21.5 && py < 23) return 6;                                      // lip of the base
  if (py >= 23 && py < 25.5) return 7;                                      // base
  return 0;
}

function pixel(x, y) {
  const px = x + 0.5, py = y + 0.5;
  if (inside(x, y)) {
    // lit from the top left: the head as a ball, the rest as a turned shape lit across each row
    let light;
    if (py < 13.5) light = (-(px - CX) - (py - 9.2)) / (1.414 * 4.3);
    else light = -(px - CX) / half(px, py) * 0.9 - (py > 23 ? 0.15 : 0);
    if (Math.hypot(px - 14.4, py - 7.6) < 1.2) return COL.pieceLit;
    if (light > 0.45) return dither(x, y, (light - 0.45) * 3) ? COL.pieceLit : COL.piece;
    if (light < -0.6) return dither(x, y, (-0.6 - light) * 4) ? COL.pieceShade : COL.pieceDark;
    if (light < -0.2) return dither(x, y, (-0.2 - light) * 3) ? COL.pieceDark : COL.piece;
    return COL.piece;
  }
  for (const [dx, dy] of [[1, 0], [-1, 0], [0, 1], [0, -1]]) if (inside(x + dx, y + dy)) return COL.ink;   // the game's dark outline
  if (inside(x - 1, y - 1) || inside(x - 2, y - 1) || (inside(x - 2, y - 2) && y > 20)) return COL.shadow;   // a shadow to the lower right
  const sq = ((x >> 3) + (y >> 3)) & 1;                                     // 8 x 8 squares
  const edge = Math.hypot(px - 16, py - 16) / 22.6;                          // darker towards the corners, dithered like the game

  const bad = results.filter(r => r.fail || r.code).length;
  console.log(bad ? `\n${bad} test file(s) failed.` : `\nAll ${results.reduce((a, r) => a + r.pass, 0)} checks passed. Screenshots: ${path.join(WORK, 'shots')}`);
  process.exit(bad ? 1 : 0);
})().catch(e => { console.error(e); process.exit(1); });
